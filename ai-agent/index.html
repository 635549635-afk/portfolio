05 / KEY MOMENTS

Agent 执行中的三个关键时刻

WHY

为什么相信 Agent 的判断？

不是告诉用户「答案是什么」，
而是让用户知道「答案从哪里来」。

判断有依据 → 建议可解释

WHEN

什么时候交还控制权？

Agent 可以判断「能不能做」，
但不替用户决定「要不要做」。

执行有边界 → 控制可交还

WHAT IF

Agent 做不下去怎么办？

异常不是执行的终点，
而是下一次「人机交接」的起点。

异常可解释 → 任务可恢复

06 / REFLECTION

从设计界面，到设计 AI 协作关系

01

从「界面」到「协作关系」

不只设计用户如何操作系统，
还要设计用户与 Agent 如何共同完成任务。

02

从「成功路径」到「不确定性」

面对审批、阻塞、超时与未知状态，
不仅要让任务可理解、可恢复，也要让人能够重新介入。

03

从「功能边界」到「责任边界」

不只判断 Agent 能不能做，
还要定义它应该做到哪里、
什么时候必须交还控制权。

设计 Agent，
不只是设计它能做什么，
更重要的是设计什么时候由它做，
什么时候交还给人。
